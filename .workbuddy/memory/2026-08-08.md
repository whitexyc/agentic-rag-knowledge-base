
## min-max 归一化深挖（2026-08-09 凌晨会话）
- 用户追问：什么是 min-max、为什么只关心相对排序。已彻底讲透并记录：
  1. min-max = (x-min)/(max-min) 线性映射到 [0,1]，代码 retriever.py::_normalize
  2. 必须归一化的根因：FTS ts_rank 10⁻³ 量级 vs 向量 cosine 0.x 量级，直接加权大数吃小数（0.006×0.3+0.90×0.7≈0.63）
  3. 只关心相对排序：检索只选 top-k 需要"序"不需要"绝对分"；min-max 保序；不用 z-score 因假设正态
  4. soft 归一化陷阱（module-035 真实坑）：min-max 只归当前结果集，跨查询不可比 → 记忆动态 K 改用绝对余弦
- 产出：CONTEXT.md 术语表新增 min-max/soft 归一化陷阱 3 条；08 文档 1.3 节新增「min-max 深挖」小节 + 追问话术；新增第 9 张图 agentic-rag-09-minmax-normalization（SVG+PNG 2x）

## 对话记录：intent 校验方案讨论（grill-with-docs 沉淀）
- 用户提问链路：confidence 怎么来的 → intent 怎么来的 → 如何校验 intent 类正确性。
- 核心结论（已落文档）：
  1. confidence 是 LLM 自报、只展示不决策；intent 是 LLM 提议 + 代码白名单裁决（决策字段要校验）。
  2. 白名单只解决"值合法"，不解决"类正确"；分类校验分离线（有 ground truth 可量化）与在线（无 ground truth 靠间接信号）。
  3. 四层方案：L1 离线 intent 评测集（扩 golden + 混淆矩阵 + eval_runs 版本化）；L2 在线不对称二次确认（只对跳过检索的高风险决策，低置信触发）；L3 检索反证（top-1 绝对余弦阈值 + 反向反思，与 check_sufficiency 镜像）；L4 反馈飞轮 + bge-m3/逻辑回归小分类器（校准真概率）。
- 产出：CONTEXT.md 新增「intent 校验领域」术语表；specs/adr/0003-intent-validation.md；08 深挖文档 1.2 节补 intent/confidence 来源 + 四层方案 + 追问话术。

## F1 指标解释已写入术语表
- 用户选中 08 文档「量化每类 F1 和混淆矩阵」，问 F1 什么意思。
- 已解释：F1 = P 与 R 的调和平均（2·P·R/(P+R)），P=精确率（挑得准）、R=召回率（挑得全）；类别不平衡时 Accuracy 骗人故用 F1；intent 场景重点盯 knowledge Recall。
- 已写入 CONTEXT.md 术语表：F1 分数、为什么不用 Accuracy、混淆矩阵 3 条。
