## Query 改写理解纠正 + 速记卡补「分诊与保真流程」
- 用户复述理解（精确→不分诊直接检索/模糊→并行检索比余弦/原高用原），我指出 4 个混淆点：
  1. 分诊是静态 FTS 术语命中（_kb_terms），不是"检索后看拿不拿得到答案"
  2. "精确"判据是词表对得上（检索质量），不是"答案对不对"（生成太贵）
  3. 特征词 = 分词过滤功能词后能在 FTS 命中的专有术语（动态判定，非预定义词表）；_RULE_TABLE 是闲聊否定信号
  4. 改写后对比必须用绝对余弦（module-035 跨 query 可比），不能直接比两个 query 的分；可加改写保真预检（改写 vs 原 query 余弦 < 阈值回退）省一次检索

## _kb_terms 实现细节 + 命名缘由落档
- 用户问 _kb_terms 具体实现/噪音去除/命名缘由。
- 实现（router.py:242-259）：三层噪音过滤——①底层 tokenize 用 `_WORD_RE=r"[一-龥a-zA-Z0-9]"` 过滤纯标点 ②`len>=2` 过滤单字 ③`_FUNCTION_STOPWORDS`（frozenset）过滤功能词（"什么/怎么/区别"等在文档广泛存在、命中无判别力）。
- 关键认知：不过滤功能词则任何 query 都命中倒排 → 分诊永远判"精确"→ 形同虚设；只留专有术语（G1/GC/线程池）才有判别力。
- 命名：kb=Knowledge Base（拿去找知识库对答案），terms=术语（非普通分词）。
- 已落档：08 文档 1.5 节分诊式改写方案补「_kb_terms 具体实现（三层过滤 + 为什么必须过滤 + 命名缘由 + 示例）」；CONTEXT.md Query 改写领域加 `_kb_terms` 条目；速记卡 3.5 节关键点 1 扩展实现细节。
